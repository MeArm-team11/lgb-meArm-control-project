本文是任务三的分步实施说明，不代表相关功能已经实现或通过实物测试。沿用任务二的命名和代码风格，由本人逐步修改草图，每一步先编译，再按条件测试。暂不进行大规模重构。

## 一、任务目标

根据考核原文，需与电路方向协作：电路方向的控制板读取四个按键，通过串口向机械臂控制板发送指令，机械臂控制板负责执行动作。

| 按键 | 功能 | 完成要求 |
| --- | --- | --- |
| 按键1 | 循环选择自动取放动作 | 第一次执行 A，第二次执行 B，第三次执行 C，第四次重新执行 A；不是按一次就无限循环 |
| 按键2 | 开始/结束录制 | 第一次按下开始记录摇杆操作，第二次按下停止并保存；动作时长大于10秒且有明显位移 |
| 按键3 | 播放 | 调取上一次保存的动作数据，完整复现 |
| 按键4 | 回中 | 返回上电时设定的初始位置 |

先用电脑串口模拟按键指令，再进行双板联调。电脑模拟只能用于开发测试，不能替代最终按键与控制板联调。

任务二当前作为基础：自动取放流程已经写入，A/B/C 点位及夹爪参数仍需填写、验证，不能把任务三的按键1接通当成任务二实物验收完成。

## 四、建议实施顺序

### 第一步：保存初始角度，再实现回中

区分三个概念：

- `bHome/fHome/rHome/cHome`：上电初始角度，也是回中目标，定义为常量。
- `bPos/fPos/rPos/cPos`：运行中不断变化的当前设定角度。
- `fHigh/rHigh`：转动底座前使用的安全抬升姿态，不等于初始位置。

先把初始角度保存为独立常量，再让当前角度变量由这些常量初始化。

回中函数按既定原则组织：大小臂先回安全姿态，再转底座，最后大小臂返回初始姿态。夹爪回初始角度的时机应结合实物检查；最初只做空载回中测试，不把回中当作夹着物体时可随意执行的急停操作。

验收：从不同的已验证姿态触发回中，最终四个设定角度与 Home 常量一致，路径不碰撞。串口显示相等并不能独立证明实际舵机已到位。

### 第二步：实现按键1循环选择 A/B/C

增加一个变量记录下次执行哪个物体，用现有风格的 `switch` 依次调用 A、B、C 的取放数据，执行后更新索引。

验收：连续触发四次分别选择 A、B、C、A；一次按键事件只启动一次动作。任务二参数仍为占位值时，不进行实际自动取放。

控制板端应处理按键消抖和“刚按下”事件，避免按住不放时重复发送。机械臂正在执行阻塞动作时，后续串口指令可能排队，不能认为它们会自动失效。

### 第三步：确定录制的数据格式与容量

先确认机械臂控制板型号及可用内存，再决定记录容量，不提前写死能支持多少帧。

一帧需要保存四个关节的设定角度，以及重放所需的时间信息。可以使用固定采样周期配合帧序号，也可以记录时间差，具体方案在实现时统一。

必须同时记录夹爪；只记录 x/y/z 无法复现完整夹取动作。

容量应覆盖大于10秒的动作，并给首尾帧留出空间。录制数组会占用运行内存，还需为现有变量、串口缓冲和函数调用保留余量。

任务原文没有明确要求断电后保留数据。初版可先考虑保存在 RAM 中，并明确断电或复位后丢失；若另有持久保存要求，再单独设计。

### 第四步：实现按键2开始和停止录制

建议流程：

1. 第一次触发：清空上一段录制计数，记录开始时间及初始姿态，进入录制状态。
2. 录制期间：继续读取摇杆，按选定采样规则记录四个角度。
3. 第二次触发：记录结束信息及末帧，停止采样并保留本次数据。
4. 数组满时：停止录制并提示，不越界写入。

建议使用 `millis()` 判断采样时机，而不是为了采样再加长时间 `delay()`。现有循环仍有 `delay(DSD)`，实现时需考虑它对采样时机的影响。

录制状态下对自动取放、回中等冲突命令应明确处理，初版可拒绝并提示，避免阻塞运动造成采样缺口。

验收：能开始、停止、重新录制；时间大于10秒；四个关节的变化均能记录；容量不足有提示。

### 第五步：实现按键3播放

播放前先判断有无有效数据。播放期间不让摇杆同时改写角度，也不允许录制与播放同时进行。

不要简单地把每帧都当成一次完整 `moveTo()` 或 `moveArm()` 动作，再额外等待一次采样周期：这可能显著拉长播放时间。应根据选定的记录时间规则安排角度输出。

播放起点与当前姿态可能不同，需要设计并验证进入首帧姿态的过渡；不能从任意位置突然跳到录制起点。准备过渡与正式录制段的重放时间应区分。

验收：按记录顺序复现四个关节的动作，时序与录制方案一致；播放结束后恢复手动控制；没有数据时仅提示，不乱动。

## 五、调速与阻塞行为

- `DSD` 控制现有逐度运动的更新间隔。
- `actionWait` 是自动取放动作之间的等待，初值不代表实际到位保证。
- 录制的采样周期、播放的时间规则与上述两个量应区分，不能不加分析地共用。
- 当前 `moveTo()`、`moveArm()`、`doAction()` 是阻塞执行；动作期间不能及时处理新的串口命令。
- 原文没有要求任务三必须实现暂停或软件急停；不要把尚未实现的停止功能写成已有能力。实物测试需留有可操作的断电方式，并防止断电后物体坠落。
